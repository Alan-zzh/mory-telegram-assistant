# Mory小助理 - 数据备份方案设计

## 用户需求分析
1. **VPS出问题时的恢复保障**：防止VPS完全损坏导致数据丢失
2. **机器人记忆保护**：避免重新训练和找回记忆的问题
3. **操作简便**：最好能在更新VPS时自动完成

## 两种方案对比

### 方案A：本地备份（推荐）
**优点**：
- 完全自动化，无需人工干预
- 更新时自动同步，保证数据实时性
- 本地文件可直接查看和恢复
- 不依赖网络通信的私聊功能

**缺点**：
- 需要增加VPS文件下载功能
- 本地需要存储空间

### 方案B：私聊指令备份
**优点**：
- 按需获取，灵活性强
- 可通过Telegram随时获取

**缺点**：
- 依赖机器人正常运行
- 需要人工操作和等待
- VPS完全故障时无法使用
- 数据量大时可能被Telegram限制

## 推荐方案：双向同步备份系统

### 核心功能
1. **更新时自动下载VPS数据**：在`vps_deploy.py`和`deploy_final.py`中添加下载功能
2. **创建本地备份目录**：按时间戳组织备份文件
3. **压缩备份**：减小存储占用
4. **保留历史版本**：保留最近7天的备份

### 备份内容
1. **数据库文件**：`mory.db`（最重要的用户数据）
2. **配置文件**：`config.json`（API密钥等关键配置）
3. **日志文件**：`mory.log`（最近的运行日志）
4. **AI模型缓存**：如果存在的话

### 技术实现

#### 1. 修改现有部署脚本
- 在`vps_deploy.py`中增加下载功能
- 在`deploy_final.py`中增加下载功能
- 创建专门的`vps_backup.py`脚本

#### 2. 创建一键备份工具
- `backup_vps_data.bat`：手动触发备份
- 集成到`vps_one_click_update.bat`中

#### 3. 恢复功能
- `restore_to_vps.py`：从本地备份恢复到VPS

## 实施步骤

```
│   │   ├── config.json        # 配置备份

│   └── backup_list.txt        # 备份清单
├── scripts/
│   ├── vps_backup.py          # 备份脚本
│   └── vps_restore.py         # 恢复脚本
└── tools/
    ├── backup_vps_data.bat    # 手动备份批处理
    └── restore_from_backup.bat # 手动恢复批处理
```

## 备份策略

### 自动触发
- **快速更新**（update模式）：只备份数据库
- **完整部署**（full模式）：备份数据库+配置
- **手动触发**：备份所有重要文件

### 保留策略
- 保留最近7天的备份
- 每周保留一个完整备份（周日）
- 每月1号保留一个月度备份

## 风险评估

### 优点
1. **数据安全**：本地有完整副本，VPS故障不影响数据
2. **操作简便**：更新时自动完成，无需额外步骤
3. **恢复快速**：可直接从本地恢复到新VPS
4. **历史追溯**：保留多个时间点备份

### 注意事项
1. **网络传输安全**：备份过程中数据加密传输
2. **本地存储安全**：备份文件需要适当保护
3. **版本兼容性**：确保备份与当前代码版本兼容
4. **磁盘空间**：监控本地备份目录大小
