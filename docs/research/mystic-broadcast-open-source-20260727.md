# 三时段传统文化播报开源方案调研（2026-07-27）

## 产品结论

三个时段不再共用“标题 + 四行短句 + 同一句免责声明”的模板，而是固定为三种信息结构：

| 时段 | 栏目 | 每日变化维度 | 群聊价值 |
|---|---|---|---|
| 早间 09:05 | 今日黄历 | 农历、干支、宜忌、冲煞、值日、星宿、方位、节气、百忌 | 提供当天可讨论的真实历法信息 |
| 午间 13:05 | 三张塔罗 | 22 张大阿卡纳无重复抽取、正逆位、主牌/助力/提醒、元素与组合解读 | 形成轻量互动话题，不冒充确定预测 |
| 晚间 20:35 | 易经一卦 | 六十四卦、本卦、一个动爻、之卦、主旨与观察问题 | 用变化结构收束一天并引出讨论 |

同一天同一时段重试结果固定，避免任务重试导致前后自相矛盾；跨日由日期种子改变。CTA 开启后，每张卡只出现一个按钮，三个时段按日随机排列“联系 Mory / 预览福利 / 自助订阅”，正文说明与按钮目标必须一致。

## 开源项目比较

### 1. 黄历

- [OPN48/cnlunar](https://github.com/OPN48/cnlunar)：MIT，824 stars，2026-07-26 更新。纯 Python，提供农历、干支、节气、每日宜忌、冲煞、十二值日、二十八星宿、吉神方位与彭祖百忌。项目已采用并锁定 `cnlunar==0.2.4`，卡片明确记录数据源版本。
- [6tail/lunar-python](https://github.com/6tail/lunar-python)：MIT，637 stars，2026-07-24 更新，字段同样完整。作为备选保留；当前不同时引入两套历法依赖，避免字段口径冲突。

选择 `cnlunar` 的原因是当前栏目需要的字段可由一个对象直接取得，依赖轻、无需远程 API 或数据库，并且许可证清晰。历法输出仍标注为传统民俗参考，不包装成事实性吉凶判断。

### 2. 易经

- [kentang2017/ichingshifa](https://github.com/kentang2017/ichingshifa)：MIT，276 stars，2026-07-27 更新，覆盖六十四卦、六爻、京房易与多种起卦法。

借鉴其“本卦—动爻—变卦”的结构，但本项目没有引入该包：群播报只需要标准八卦线型、文王六十四卦序和单爻翻转，内部实现可以保持轻量、确定、可测试，避免把复杂占筮依赖带入生产。六十四卦传统名称属于公共领域资料，没有复制项目的解释文本。

### 3. 塔罗

- [LindseyB/tarot-api](https://github.com/LindseyB/tarot-api)：MIT，65 stars，2026-07-12 更新，验证了“牌名 + 正位义 + 逆位义”的结构适合 API 化内容生产。

没有接远程 API，也没有照搬英文文案。本项目内部策展 22 张大阿卡纳的中文关键词、元素与正逆位提示，按“主牌 / 助力 / 提醒”组成三张无重复牌阵。这样既保留随机组合空间，也不会因外部 API 不稳定导致定时任务失败。

## 未采用方案

- 不使用无许可证或许可证不清晰的牌库。
- 不把三种栏目混在任意时段随机抽取；时段身份固定，内容内部随机。
- 不让 LLM自由生成农历、卦象或牌名等基础事实，防止编造。
- 不在一张卡同时放多个销售入口；专业内容与转化动作必须保持一一对应。
- 不生成“今天一定会怎样”“替你决定”等确定性断言。

## 验收口径

1. 早间卡能从真实日期复算出农历与至少两类历法字段。
2. 午间卡固定三张不同牌，每张含正/逆位，正文有组合解读而非一句口号。
3. 晚间卡的变卦必须由本卦一个真实爻位翻转得到。
4. 同日重试完全一致，跨日有足够组合变化。
5. 每条最多一个 CTA，CTA 关闭时正文和键盘都不出现入口。
6. Telegram Rich Message 与 HTML 回退都保留分区排版及 `@MoryMateBot` 署名。
