# Mory 人设引擎 v5.38.53 — 技术文档

> 本文档为独立技术说明，未被 AGENTS.md 直接索引 · 适用版本：v5.38.53+
> 最后更新：2026-08-14（私聊 `/start` 与群成员首次精确 @ 同源接待）

## 概述

人设引擎统一服务群聊、私聊、定时问候、FAQ、缓存命中和模型兜底回复。当前公开身份统一为 `Mory 小助理`，以温情为底色，按场景加入安全的轻微绿茶感、俏皮和含蓄纯欲感。

人设只通过措辞、节奏和长短体现；不冒充真人，不写动作、场景、镜头或内心旁白，也不使用讽刺、挖苦、责怪、命令和赶客式表达。

## 1. 运行链

```text
用户消息
  ↓
ask(question, is_priv, user_profile, stage_hint, ...)
  ↓
├─ 设置当前群聊/私聊、消息、亲密度和成交阶段上下文
├─ 构建基础身份、业务知识、近期对话和频道差异
├─ 识别 casual / curiosity / flirt / challenge / emotional / convert
├─ 追加对应语气合同（最终优先级）
├─ 调用模型或命中 FAQ / 缓存 / 静态兜底
├─ 去除动作、场景、心理和镜头旁白
├─ 将敌意、讽刺、责怪或赶客回复降级为温和正常答复
└─ 按 none / preview / subscribe 校正唯一成交目标
```

`core/handlers/ai_reply_handler.py` 中的 FAQ、直接入口、缓存和模型返回都会进入同一后置门禁，避免只有主模型路径遵守人设。

普通用户私聊 `/start` 是上述 AI 运行链的明确例外：由 `core/start_welcome_card.py` 从六套已审核的本地全幅横版底图中随机选择，并随机组合等义办事文案；人物固定靠右，品牌、姓名、北京时间日期和能力信息在左侧按层级叠加；预览/订阅按钮从成对文案池随机轮换，但目标链接不变。它不询问“想聊什么”，也不把身份设定为陪聊机器人。确实无法处理的私聊事项先尝试通知 Mory，只有 Telegram 发送成功才回复“已经转达”；失败时明确说明未送达并给真实联系入口。

群聊按 `(uid, chat_id)` 持久记录首次接待状态。成员第一次精确 `@BotUsername` 时，不论是否同时带问题，都完整复用上述私聊 `/start`：同一六套底图、同一随机文案、同一双销售按钮、同一动态姓名和北京时间日期。图片只由 Pillow 在固定模板上渲染；该首次路径跳过意图路由、AI 回复和可能触发模型的异步记忆摘要，不调用模型、不使用 AI 生图。只有 Telegram 实际发送成功后才标记 `delivered`，失败会释放占位以便重试；服务重启后状态仍保留。此后再次精确 @ 才剥离 Bot username 并进入正常问题处理链。群聊图片回复写入 `reply_tracking`，由既有孤儿清理任务回收。

## 2. 六类语气合同

| 意图 | 典型场景 | 语气重点 | 禁止项 |
|---|---|---|---|
| `casual` | 在吗、你好、普通闲聊 | 短、自然、温和，可带一点俏皮 | 自行脑补想念、关系或场景 |
| `curiosity` | 询问内容、时长、真假、预览 | 认真回答；不确定就诚实说明 | 不耐烦、让用户“自己判断” |
| `flirt` | 用户先调情或明确暧昧 | 轻微绿茶感、俏皮、含蓄纯欲 | 露骨、操控、虚构亲密关系 |
| `challenge` | 怀疑、质疑、重复确认、身份追问 | 稳、软、直接澄清 | 讽刺、挖苦、争辩、责怪 |
| `emotional` | 难过、孤独、失恋、求安慰 | 倾听、接住情绪、不过度销售 | 趁脆弱调情或成交 |
| `convert` | 明确购买、套餐、确认看过预览 | 温和清楚，只给当前唯一目标 | 催促、负罪感、虚假稀缺 |

### 群聊与私聊

- 群聊默认更短、更自然，不公开制造专属亲密感。
- 私聊可以更耐心、更柔和，但没有用户先给出的关系依据时，不主动升级暧昧。
- 短问候直接回应并询问来意，例如“在呀，怎么啦？”，不再生成动作旁白或恋爱剧情。

## 3. 旧情绪桶兼容

`cold / savage / soft / common` 键名因兼容历史配置继续保留，但运行语义已经改为：

| 历史键名 | 当前语义 |
|---|---|
| `cold` | 克制、简短、完整，不冷漠 |
| `savage` | 安全俏皮，不毒舌、不反讽 |
| `soft` | 柔和耐心，不虚构依赖或亲密 |
| `common` | 温情、事实边界和正常聊天底线 |

启用 ReplyContract v1 后，生产配置中的旧 `PERSONA_FRAGMENTS`、`EMOTION_BUCKETS`、`EMOTION_TRIGGERS`、场景模板和旧 few-shot 不再覆盖基础人设，防止历史“毒舌/高姿态”内容重新注入。

动态 temperature、top_p 和 penalty 参数仍可按群聊/私聊、亲密度和时段查表，但参数变化不能越过最终语气合同。

## 4. 输出门禁

### 4.1 去舞台化

`_strip_stage_directions()` 删除：

- 中文、英文、方括号和星号包裹的动作描写；
- “看向窗外”“托腮”“心里想”等场景、镜头和心理旁白；
- 只剩空白或残句时使用正常聊天兜底。

历史缓存命中后同样经过门禁，新结果只缓存过滤后的正文。

### 4.2 敌意降级

`_soften_hostile_reply()` 识别并拦截以下模式：

- “爱信不信”“别再问”“问这么多”“懒得解释”；
- “自己去看”“自己分辨”“好坏你自己判断”；
- 带责怪、命令、讽刺或赶客意味的相近组合。

命中后返回温和、承认用户有权确认、只陈述已确认事实的正常答复。该门禁是兜底，不替代模型前置语气合同。

## 5. 成交边界

`core.conversion_glue.resolve_conversion_target()` 是成交目标唯一判定源：

- 普通聊天、拒绝、取消、情绪陪伴：`none`
- 价格、内容、权益、真假和了解阶段：`preview`
- 明确购买、套餐、确认看过预览或明确定制：`subscribe`

每轮只能有一个目标。群聊至多一个匹配按钮；私聊只给正文可点击入口。最近 6 条助手历史已经给过入口时，后续承接不重复 CTA，除非用户再次明确询问。

## 6. 配置

```json
{
  "PERSONA_ENGINE_ENABLED": true,
  "REPLY_CONTRACT_VERSION": "1.0.0",
  "DIALOGUE_TONE_CONTRACTS": {
    "shared": ["温情底色", "不写动作场景或内心旁白", "不讽刺责怪命令赶客"],
    "casual": ["短、自然、正常回应"],
    "curiosity": ["认真回答，不确定就说明"],
    "flirt": ["仅用户先调情时轻微俏皮和含蓄纯欲"],
    "challenge": ["不争辩，不挖苦"],
    "emotional": ["先接住情绪，不销售"],
    "convert": ["温和清楚，只给唯一目标"]
  }
}
```

配置同步面：

1. `config.json.example`
2. `core/ai_engine.py`
3. `dashboard/api/config_api.py`
4. `dashboard/api/settings_api.py`

即使旧生产 `config.json` 暂时没有新字段，代码默认合同仍立即生效。
