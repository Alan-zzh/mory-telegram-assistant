## 一、现状取证结论（经对抗式核验）

### 1.1 三时段传统文化栏目（确定性引擎，0 LLM token）

| 时段 | mode | 引擎现状 | 内容池规模 |
|------|------|---------|-----------|
| 早间 | almanac | cnlunar 真实农历：宜忌/冲煞/值日(含黄黑道)/星宿/吉神方位/节气/彭祖百忌/十二时辰吉凶/财神喜神方位 | 点评 4 分支 × 各 4 条 |
| 午间 | tarot | 22 大阿卡纳抽 3 无重复（主牌/助力/提醒），正逆位（已是受阻/向内式），主导元素观察 | 牌义 22×2×3 关键词；点评句式 5 × 动作 10 |
| 晚间 | iching | 64 卦 + 动爻 → 本卦/之卦，卦意观察 + 今晚一问 | 64 卦主旨词；点评句式 5 × 问题 8 |

- 随机机制：`_stable_rng`（日期稳定，同日重试一致）+ `_insight_rng`（点评独立流）。隔离边界已核实：抽牌随机数先于点评消费，扩点评池必然改变当天选中文案但不扰动牌面序列。
- 排版三层：图片卡 → Rich Message → HTML；时辰吉凶/方位已被图片卡渲染（`broadcast_image_payload.py:94-106`）。
- 私聊占卜：7 命令 + 关键词识别，本地生成 0 token；**现状对金钱/健康/法律话题无任何守卫（合规缺口，P4 处理）**。

### 1.2 早午晚问候（LLM 生成）

- 4 个 prompt（morning/afternoon/evening/night），25-55 字两句内，seed 随机；长度已落在业界最佳区间，不改。
- 质量门禁 `is_usable_greeting`：night 下限 25 字符、其余 30，上限 120；31 词 ban 表；失败本轮不发送，无固定 fallback 池。
- theme_engine THEME_POOL/TONE_POOL 当前为零消费死链路（见 D1 决策项）。

## 二、优化方案 v2（按优先级排序）

### P0 易经栏目信息密度补强（专业评审"最值得做"项，优先级最高）

晚间栏是三栏目中信息最薄的（塔罗有 22×2 关键词、黄历有 cnlunar 全字段，易经只有两个主旨词+一问）：

1. 64 卦各配一行「卦辞白话 + 大象传映射」（如 泰卦：「天地交而万物通；上下交而志同 → 打开沟通渠道的时机」）。
   - 质控要点（专业评审给定）：原文以通行本为准；术语表先行统一（元亨利贞/悔吝厉咎/孚）；生僻卦名注音（屯 zhūn、比 bì、噬嗑 shì hé）；险难卦不鸡汤化（坎就是险）；逐条与原卦辞对照防张冠李戴。
   - 之卦保持主旨词现状（信息不对称已知悉，避免卡片超载）。
2. 动爻爻辞 384 条不做：部分覆盖导致产品不一致，全量审校成本高、轻娱乐场景边际价值低（专业+对抗两方一致裁决）。

### P1 三栏目扩池与现代化（吸收全部硬伤修复）

1. **塔罗牌阵框架轮换（带开关 + 独立随机流）**
   - 新增 2 个备选框架：情境/行动/结果、现状/挑战/指引（弃"身/心灵"——撞健康红线）。
   - 框架选择器挂**新增独立 rng 流**（新 salt），严禁挂现有 `_stable_rng` 消费序列——否则多消耗一次随机数移动整条牌面，破坏"按日期稳定起卦"产品合同（对抗式 T3 陷阱）。
   - 默认框架"主牌/助力/提醒"占比 ≥80%，保栏目身份认知；开关 `MYSTIC_BROADCAST_CONFIG.tarot_spread_rotation_enabled = False` 默认关闭。
   - `_TAROT_ACTIONS` 按框架分池（每框架独立动作池），或统一改写为角色中立句；既有 `"牌阵从"` 开篇骨架仅在默认框架保留。
2. **塔罗大牌关键词扩池（替代原 78 全库）**：22 张 × 正逆位 3→5 词；同步产出小牌策展规范模板（宫廷牌=人物特质/行事方式而非事件牌；花色元素一致；数字牌循 Ace种子→10完成 数序；逆位受阻式非取反；星币不写"财运到"断言），规范验收后再议全库另立项。
3. **易经今晚一问扩池**：8→16 条。
4. **黄历三处现代化**：
   - 吉时呈现：直接列吉时辰名+钟点区间（如「卯时 5:00-7:00 · 吉」），标注"依传统时辰表"；子时跨午夜注明 23:00-01:00；不与值神并列以免暗示因果。
   - 值神解释：12 条静态字典（司命昼吉夜不利、朱雀口舌、金匮[从库内拼写]财星等）；判定算法零开发，cnlunar 已输出。
   - 宜忌术语白话注沿用 `_THING_ALIASES` 补齐常见项；almanac 点评各分支 4→8 条（新条目须含分支关键词，保住 golden 测试 `"动土" in insight` 断言）。
5. **免责尾注（双路径覆盖 + 开关）**
   - 文案：「内容仅供娱乐与传统文化参考，不构成决策依据」（专业评审认可的双重定位表述；不罗列医疗/法律清单以免像法律文本）。
   - 三栏目 payload：并入现有 footer/closing 渲染位（**不得渲染为新 block**，否则破 `<h3> 数 == blocks 数` 断言）；位置卡片最底部小字、与 CTA 视觉分隔、不插在 insight 与按钮之间。
   - 私聊占卜 text 同步追加同一行尾注（合规目标两条路径同覆盖）。
   - 开关 `MYSTIC_BROADCAST_CONFIG.disclaimer_note_enabled = False`；配置三处同步（example + 代码默认值 + Dashboard 白名单 settings_api.py + config_compat.py 规范化默认值）。
   - 口径张力登记：现有 mystic_contact 文案「易经问事越具体越准」（broadcast_cta.py:119）带效力暗示，与尾注并存时以尾注兜底，不改 CTA（本次不动 CTA 合同）。

### P3 greeting 节气联动（复用在产依赖）

1. greeting prompt 注入当日节气标签：`import cnlunar` 复用（与 mystic 同依赖，零新表零硬编码），当日结果缓存一次。
2. 注入方式走 `{seed_hint}` 占位符，仅提供意象词（如「今日处暑」），prompt 中"不虚构天气"红线不受影响（节气≠天气描述，注入的是日期事实不是景物虚构）。
3. 图片卡 badge 节气联动：badge 取值链在 `GREETING_CONFIG.{period}_badge` 基础上支持节气名后缀（需改 `greeting_task.py:122` 取值逻辑，属新开发非纯配置）；视觉主题色切换需扩展 `resolve_theme_options`（当前仅 period 维度，broadcast_image_card.py:1433-1450），列为可选增强不阻塞主体。
4. 开关 `GREETING_CONFIG.solar_term_hint_enabled = False`。

### P4 私聊占卜敏感分流（合规缺口修复，触发顺序锁定）

- **已取证现状违规**：用户问"我该买哪支股票，帮我算卦"→ 命中 iching → 直出完整卦象，主题词含"该买哪支股票"，全链无守卫（分发第一分支 `keyword_trigger.py:564`，生产 `private_reply_enabled=true`）。
- 触发顺序锁定：**先命中占卜意图（现有 resolve_private_mystic_mode 逻辑不变），再在占卜分支内查敏感词**；绝不独立宽匹配扫全量私聊（否则吞掉正常聊天，违背后置门禁红线精神、中断消息分发主链）。
- 敏感域：重大疾病/医疗、法律纠纷、具体金融投资决策三类；命中后回复中性承接文案（明确"这类问题更适合咨询专业人士"+ 可选继续娱乐占卜说明，**不携带任何 @ 入口**）。
- 承接文案属敏感话题承接，须经管理员确认后入库（AGENTS.md 合同要求）；不做固定 fallback 式泛用模板，仅作用于占卜分支内部。
- 附正常话术反例测试：至少覆盖"帮我算卦看工作""给我抽一下塔罗看感情""想看看风水"等既有正常请求不被误拦。
- 前置数据动作（P4.2 先行）：翻现有日志统计私聊占卜命中率与敏感词实际出现率，只读操作，验证分流必要性与阈值。

### D1 theme_engine 接入-or-删除决策（先决策再动代码）

- 事实：THEME_POOL/TONE_POOL 零消费（唯一调用丢弃返回值）。
- 选项 A（删除）：整池移除减维护面，`scheduled_broadcast.py:309` 死调用一并清。
- 选项 B（接入）：把 theme/tone 真实拼进 ai_engine 的 mode persona（ai_engine.py:1997 一带），让 greeting 每天有确定性主题差异——这是 greeting 多样性的真杠杆。
- 建议 B，但涉及 prompt 行为变化，**待老板拍板后再实施**。

### 清理项（去陈旧铁律）

- `data/tarot_cards.json`（22 张吉凶式单句，与栏目克制口径冲突）+ `KeywordManager.get_tarot_cards()` 全仓零调用 → 删除或在 AI_DEBUG_HISTORY 登记技术债给迁移计划。
