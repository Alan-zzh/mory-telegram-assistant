# docs/plans/ — 计划与实施方案

本目录存放所有计划、实施方案、任务拆解、重构方案、后续执行计划。

## 规则

- 所有计划必须标明：目标、范围、当前状态、执行步骤、验证方式
- 计划完成后更新状态（已完成 / 部分完成 / 未执行 / 已废弃）
- 过时计划迁入 `docs/archive/`
- 计划文档需与 `README.md` 和 `project_snapshot.md` 区分：这里写"将来要做什么"，而非"现在是什么"

## 当前状态

**有 1 份已完结计划**：`remediation-2026-08.md`（2026-08-05 v5.38.22 四项整改收尾，已执行完成）。历史整改见 `remediation_roadmap.md`（2026-07-07 完结）。

所有计划直接在以下位置跟踪：

| 跟踪方式 | 说明 |
|----------|------|
| **CHANGELOG.md** | 已完成或正在进行的用户可感知变更（含每次 release 的详细内容、阶段整合策略） |
| **AGENTS.md** | 长期项目规则与技术约束（如 §7 失败升级机制、§5 技术选型约束） |
| **docs/vision/** | 长期愿景与产品方向（见 `docs/vision/README.md`） |
| **项目日常开发** | 直接通过 CHANGELOG 迭代，未单独拆分为独立计划文档 |

> 若后续有需要多人协作或跨多个版本执行的复杂计划，应在此目录新建文档，并同步更新本 README 的索引。
